      Simulation workflow qualification

      This record qualifies the development recording/restart workflow against native CPU, Warp CPU and RTX 5060 CUDA execution. It accompanies the usage guide and adaptive-method assessment. It establishes implementation and numerical behavior for the profiles below, not experimental validity or a GPU performance claim.

      Source and environment

      Section titled “Source and environment”

      The qualification extends Stage 2A c6e8bf0967 and Stage 2B 7a53906faa with the forcing, reduced observation, GPU/split restart and writer implementation in the commit introducing this record. The selected checkout was /tmp/particula-stage-02b, with PYTHONPATH=. and its existing .venv. The backend matrix includes native NumPy CPU RK23/ROS2, Warp 1.11.1 CPU and native CUDA on RTX 5060 (sm_120; driver 13.4, toolkit 12.9).

      The source package identifies itself as 0.3.1. Installed distribution metadata in the example environment still identifies 0.2.14; no dependency upgrade was used to hide that mismatch. Example provenance includes the executing source, revision and dirty state. Exact restart checks package/runtime versions and configuration, but a version string alone does not identify modified code. Retain the source revision and study inputs alongside saved research output.

      The independent forcing tests specify all equations and reference inputs in forcing_test.py; they do not derive their oracle from the production rate. Restart tests compare future state and random continuation, not merely the loaded starting arrays. CUDA cases ran rather than being replaced by Warp CPU.

      Formats and compatibility

      Section titled “Formats and compatibility”

      Analysis uses versioned ZIP/JSON/NPY arrays. HDF5 and Zarr offer chunking but add dependencies and more complex multi-object publication; bounded single-file histories fit atomic replacement. Full trajectories are deliberately opt-in and limited. Exact restart uses a distinct schema and a fixed record/enum codec, never pickle, arbitrary imports or serialized live process callbacks.

      Prepared files preserve SimulationCheckpoint v2 and ResidentCheckpoint v5 canonical bytes; lossy CPU inspection carriers are regenerated from that authority. Native CPU and split records use schema 1. Adaptive CPU records use schema 2 for explicit table forcing; adaptive GPU records use schema 3 for ROS3 and exact unchanged-coordinate unscaling. Coupled GPU records use their own schema 1 for complete event boundaries. Container schemas remain separate from record versions. Unsupported schemas are rejected without guessed migration. Prepared/custom adapters remain caller-supplied; loading is data reconstruction, and resume validates the owner-specific configuration.

      Opaque adaptive forcing and arbitrary split callbacks have no exact disk identity. GPU restart requires the saved device profile, with CUDA UUID matching for adaptive owners. Existing prepared-device constraints remain authoritative. These restrictions are supported-profile boundaries, not claims that any Python callback or machine can reproduce the same future trajectory.

      Executed validation

      Commands ran from the selected worktree. Logs remain under ignored .artifacts/.

      • Tooling and examples: 565 passed, 1 skipped. The skip remains outside the execution claim. Standard Ruff/format passed (753 files); standard Mypy passed (673 sources). Untyped function bodies are outside standard Mypy’s scope.
      • Final combined numerical/workflow suite: 158 passed with warnings as errors, including actual CUDA. All fourteen runtime modules changed by Stage 2B have 90% aggregate focused coverage, using directory-based coverage discovery and explicit report paths. This avoids importing/unloading NumPy during dotted discovery.
      • All six new workflow guide Python blocks executed, including CUDA adaptive restart and prepared observation/restart. The full first CPU example refreshed successfully; its two-case 300-DPI figure was visually inspected. The saved bundle includes compact plot summaries, not full restart files.
      • Website: 554 pages built; 684 HTML pages, 319 API modules and 130 redirects verified with zero errors. Rendered structure check also passed. The final prepared codec matrix, including mixed host RNG, passed 23 tests.

      Scientific and operational limits

      Section titled “Scientific and operational limits”

      The first example’s 10 and 20 µg/m³ vapor cases reach about 136.69 and 162.13 nm from 100 nm over 600 s, with species mass residuals below 7e-16 relative. These are illustrative model predictions, not measurements. Conserved mass and exact restart do not establish physical accuracy. Local adaptive tolerances are not global error guarantees, and changing output boundaries can change a numerical or stochastic trajectory. Compression/download cost is explicit and no workload speedup is inferred from correctness checks.

      Review examined state detachment, native measures and species maps, accepted versus trial publication, exact coordinate restoration, forcing one-sidedness, RNG and field continuation, atomic replacement and non-executable loading. The capture-save gap was corrected and covered by an actual CUDA regression. Publication and merge status belong to the plan delivery records; these results do not assert a released package or a deployed documentation site.

      Coupled GPU event boundaries

      Section titled “Coupled GPU event boundaries”

      The follow-through implementation adds GPUCoupledSimulation: fixed native source/collision/removal/dilution events and a separately controlled GPU condensation flow. It preserves persistent event buffers/RNG, explicit sequential order and full host transfer boundaries. The controller resets at every event boundary. Its distinct schema-1 checkpoint contains canonical event continuation, condensation identity, scalar controls, order and work counters; the outer archive codec remains explicit data, without pickle.

      The focused coupled/numerics/archive/restart selection passed 65 tests with one deliberate Warp-CPU capture skip on Warp CPU and the RTX 5060. It includes exact disk continuation with source and Brownian collisions, captured events, rejected condensation trials without repeated event draws, unchanged caller state and event-buffer identity, independent dilution/inventory checks, empty-population continuation, shorter-bound rejection and faulted-cycle observation rejection. The latter retains the last complete public clock while rejecting further snapshots and checkpoints after partial physical work. Changed condensation physics rejects before device access. Unsupported event families reject before allocation. All-package Mypy and Ruff checks passed.

      These tests do not substitute for the full published workloads. The cyclic chamber still requires all 32 boxes, 8,192 slots, 600 one-second cycles, 128-event pulses and complete second-half restart. The forcing example retains 16 boxes, 4,096 slots, 6,000 one-microsecond intervals and the full doubled-step refinement with unchanged control times. Their updated sources and compact recording are implemented. Both full publications were launched in a detached checkout pinned to 480ecf2c1a, separately from subsequent edits. The forcing publication and figure inspection subsequently completed, as recorded below. The cyclic chamber still requires full-workload completion and figure review.
