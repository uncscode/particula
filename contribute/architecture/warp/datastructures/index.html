    Data Structures for Aerosol Simulation

    These are standalone Warp teaching patterns, not Particula native container or process APIs. Snippets share surrounding definitions and may require a CUDA device where explicitly selected. They do not validate coupled aerosol physics, conservation, performance or public-step autodiff. For the supported native path, use GPU foundations and its executed direct/resident examples.

    Overview

    Section titled “Overview”

    NVIDIA Warp provides a rich set of data structures optimized for parallel computation on both CPU and GPU. For particula, these structures efficiently represent particle populations, aerosol properties, and simulation state.

    Data Transfer Optimization

    Section titled “Data Transfer Optimization”

    For environment state, the same rule applies through explicit helper APIs only. particula.gpu.WarpEnvironmentData is the Warp-side mirror of particula.gas.EnvironmentData: the CPU object owns the host-side thermodynamic state, while the Warp object keeps the same logical fields in Warp arrays on the selected device. Callers choose when to cross the CPU↔GPU boundary with to_warp_environment_data() and from_warp_environment_data(). Kernels and runnables do not perform hidden CPU↔GPU environment transfers or synchronization for you, and CUDA support is optional rather than required for this helper workflow.

    EnvironmentData Round-Trip Example

    Section titled “EnvironmentData Round-Trip Example”

    This explicit round trip keeps the same shape contract on both sides of the transfer:

    • temperature: (n_boxes,)
    • pressure: (n_boxes,)
    • saturation_ratio: (n_boxes, n_species)

    Use device="cpu" for a portable round trip on any Warp installation. device="cuda" is optional and should be used only when Warp CUDA support is available. The important design rule is that transfer boundaries stay visible: build EnvironmentData, convert explicitly to WarpEnvironmentData, let kernels or runnables consume that mirror in place, and convert back to EnvironmentData only when CPU-side analysis or control flow actually needs the data.
