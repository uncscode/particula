# Particle number spectra on explicit diameter edges

**Original recommendation.** Add a CPU particle-property function for binning point diameters with number-density weights, a thin adapter for native particle data, and exact conversions between integrated bin density and density per decade. Migrate the Π Chamber and Pallas cloud-probe studies first. Together they exercise both entry paths with independently checkable saved results. Schedule conservative redistribution of pre-binned data separately because splitting a measured interval requires an assumption about its contents.

Researched on 2026-11-27 against upstream `main` at `d5560b4c9e48ae42e8ce59fcf71e19aade5733d5` (Particula 0.3.6). The issue used `bf91687e52`. [Issue #1743](https://github.com/uncscode/particula/issues/1743)

## Implementation and migration evidence

The implementation includes all four steps below, including conservative rebinning. The five public functions and their SI contracts are described in the [data model guide](../docs/guide/data-model/index.md#diameter-spectra). The [property tests](../particula/particles/properties/tests/number_spectrum_test.py) exercise unequal box volumes, exact boundary neighbors, both final-edge conventions, and interpolation of cumulative number on independent grids.

- Both Π Chamber CUDA replays reproduced all 2,304 archived bin densities within 1.9 × 10⁻¹¹ cm⁻³. The [restart test](../examples_tests/pi_chamber_spectra_test.py) checks each starting bin independently.
- The [Pallas figure test](../examples_tests/pallas_number_spectrum_test.py) integrates the rendered probe curves against the archived attribution totals below. The three daily probe grids also agree with differences of interpolated cumulative counts.
- Bai's 808 retained wet-radius columns reproduced all 146 fine bins within 5.7 × 10⁻¹² cm⁻³. The Jeju replay recovered all 180 published window rows and reproduced the gallery spectrum paths exactly.
- The [Voliotis verifier](../studies/voliotis-2022/joint/resolved/verify.py) compares all 273 rows with an independent cumulative-number calculation using a different count series for each time and runs the identical-particle control.
- Other migrations cover MAM4xx, SEA2CLOUD, dry-diameter and weighted-particle diagnostics, and the affected GPU, emissions, condensation and nucleation examples. Computational-slot counts, imager event counts, signed charge histograms, arrival fluxes and independent numerical controls retain their original definitions.

## Which design to choose

| Approach | Benefit | Cost or deciding constraint |
| --- | --- | --- |
| **Dedicated functions under particle properties** | Raw arrays serve both instruments and study outputs. Native callers can supply a tagged particle population. One implementation owns edge inclusion, tails and log widths. | Adds a small public API and requires explicit unit conversion at study boundaries. Recommended for the first delivery. |
| Extend `SizerConverter` and its strategies | Existing users could select explicit edges within the familiar conversion interface. Reasonable if the need were confined to changing the measure of already-binned data. | Its input has one diameter per value. Point binning instead takes one diameter per particle, an independent edge vector, and returns two tails. Inferring the operation from array length would make existing calls ambiguous. An explicit new entry point would still be needed. |
| Introduce a reusable diameter-grid object | A fixed grid could cache widths, geometric centers and mappings to other grids. Attractive when a study repeatedly applies the same source-to-target transformation. | More lifecycle and API design before the first two callers need it. Revisit with the Voliotis rebinning work if repeated mapping justifies construction and caching. The optics grid already binds wavelengths and retrieval groups, which particle studies do not supply. |

A method only on `ParticleData` would help native simulations but leave both first adopters doing their own arithmetic. The proposed adapter can be a free function alongside the raw-array entry point.

## Proposed first-delivery contract

The proposed parameter names identify the physical quantities. Document diameter and diameter edges in metres and number density in m⁻³ in the function docstrings. Put the implementation in `particula/particles/properties/number_spectrum.py`.

- `get_binned_number_spectrum(diameter, number_density, diameter_edges)` accepts matching real arrays with shape `(..., slots)` and shared 1-D edges. Return a named result with `bin_number_density` of shape `(..., bins)` and `below_range`, `above_range` of shape `(...,)`. Each output is m⁻³. Accumulate in float64 and preserve each leading row, including independent boxes, times and replicates.
- Intervals include the lower endpoint and exclude the upper endpoint, except that the last interval includes its upper endpoint. Classify with the supplied physical diameters directly. Compute tail weights independently. A single bin, all-empty input, all-out-of-range input, unsorted particles and repeated diameters each have a defined result. For example, the issue's weights sum to 18 m⁻³, of which 2 and 8 fall in the bins, 1 below and 7 above.
- Require at least two finite, strictly increasing, positive edges in metres. Reject complex inputs, incompatible shapes, nonfinite or negative weights, and invalid occupied diameters. Permit a zero-diameter, zero-weight empty slot. Test exact edges and their immediate floating-point neighbors, including the final edge. Avoid clipping or a tolerance that moves particles between bins.
- `get_particle_number_spectrum(particles, diameter_edges)` takes labeled CPU `ParticleData`. Use twice `radii` and the validated `slot_concentration_density`, keep one row per box, and skip zero weight. Check the resolved slot contract before masking. Reject unknown representations and `continuous_pdf`; interval integration of a tabulated dN/dr requires mapping D to r=D/2 and a quadrature rule at cut boundaries. Callers with optical, dry or mobility diameters can use the raw-array entry point with their own diameter definitions.
- Add explicit functions for bin density → dN/dlog₁₀D and its inverse with the bin axis last. A bin's dimensionless width is log₁₀(D_high/D_low). Divide an integrated number by this width to get m⁻³ decade⁻¹, and multiply to recover the bin density. Preserve grouped dimensions and check finite positive representable widths. Study adapters convert µm to m and cm⁻³ to m⁻³ at the boundary, and convert back for published values. Range tails have integrated units only.

## Implementation sequence and acceptance

1. **Implement the array functions and freeze the numerical contract.** Add adjacent property tests for the issue example, single-bin endpoints, unequal widths, leading axes, invalid data and no input mutation. Use direct per-interval masks as an independent oracle. On [1, 2, 8] µm the second log width is twice the first, so equal per-decade densities must yield a 1:2 bin-density ratio. Test per-bin answers and per-row closure separately, including separated weight scales so a large first bin cannot hide loss from a small later bin.
2. **Connect native state and optics.** Add representation-specific tests beside the existing [particle-data tests](../particula/particles/tests/particle_data_test.py). A discrete 1 m³ reference with densities [2, 8] should match resolved boxes of 0.5 and 2 m³ containing raw counts [1, 4] and [4, 16] respectively, with diameters strictly inside the two bins. Compare bins and tails to `number_density` per box. Include multiple species, free slots, a zero-weight discrete representative, an invalid resolved slot, PDF and untagged rejection. Exercise both optics measures, its 2-D group case and current public imports. Document supported diameter and concentration measures in the [native guide](../docs/guide/data-model/index.md) and cross-link the [optics guide](../docs/guide/optics/index.md).
3. **Migrate Π Chamber and Pallas against saved values.** Use the pinned [Π Chamber JSON](../website/results/pi-chamber-spectra/data.json) and [existing tests](../examples_tests/pi_chamber_spectra_test.py). On CPU, regenerate time-zero cohorts from the recorded seed and restart for both runs, compare all four cases bin by bin, and compare per-decade rendering for every saved time. For publication, run the registered [CUDA example](../website/examples.json) with the same seeds and time steps and compare full `bin_cm3`, cloud sampling bounds and relative spectrum differences before refreshing saved outputs. The new helper itself needs only CPU tests. For Pallas, use the [12 saved intervals per day](../docs/data/pallas-cloud-probes/distributions.csv), compare each rendered density against the previous expression, integrate the five intervals from 6 to 13 µm, and compare the totals with [independent attribution rows](../docs/data/pallas-cloud-probes/attribution.csv). Preserve figure units, bounds and percentage curves.
4. **Evaluate conservative rebinning as a follow-up.** Accept integrated source density and disjoint source and target partitions. Give each target the fraction of each source interval's log width that it overlaps, assuming constant dN/dlog₁₀D within that source interval. Return integrated density and tails for a contiguous target partition, then use the same per-decade conversion if requested. Verify identity, merges, splits, zero overlap, partial coverage, and closure. For example, splitting 12 m⁻³ over [1, 4] µm at 2 µm gives [6, 6]. Compare independently with differences of cumulative number interpolated in log diameter. Voliotis should compute the target grid per time slice or gather saved row indices from a complete grid. Rows repeated across times or removed by the quality filter cannot collectively be treated as a single partition. Preserve its time selection and `air` correction. Account separately for particles already discarded by the recording kernel outside its source grid.
