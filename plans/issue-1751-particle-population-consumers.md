# Make particle population reads and writes explicit

Implement [issue #1751](https://github.com/uncscode/particula/issues/1751) as one behavior-preserving PR against Particula 0.3.6. Give native CPU physics one way to obtain each slot's contribution to number density, give the binned coagulation writer an explicit density-to-storage boundary, and document which remaining consumers require raw arrays. This makes the later storage change reviewable without changing a simulation's meaning along the way.

Research baseline: upstream `f708cc03806467891d92af65e10b9087d321e15a`. The production `particula/` tree matches the issue's audit revision `27a315e983`. [#1752](https://github.com/uncscode/particula/issues/1752) owns the field rename, extensive storage, non-unit bin/PDF admission, persistence changes and version bump. [#1753](https://github.com/uncscode/particula/issues/1753) owns the broader documentation and study migration. Today's fixed-volume dilution still scales raw particle weights and every gas lane.

## Choose the quantity before changing a caller

Let `c` denote the existing writable array, `V` the represented air volume in m³, and `h_i` the trapezoidal node width in metres on the **radius** grid.

| Kind in 0.3.6 | Raw slot value | Value for a size-resolved rate or a plot of the native distribution | Weight for a sum over particles, m⁻³ |
| --- | --- | --- | --- |
| Discrete | Bin number density, m⁻³, V = 1 m³ | c | c |
| Continuous PDF | dn/dr, m⁻⁴, V = 1 m³ | c | c × hᵢ |
| Resolved | Represented count, including fractional multiplicity, V > 0 | c/V | c/V |

Use `slot_concentration_density` for the middle column. Use the last column for a sum of per-particle contributions, such as gas depletion or optical extinction. A PDF coagulation gain/loss routine that already integrates over radius consumes the middle column. Giving it the last column would apply the grid spacing twice. Keep the aggregate APIs for total number per m³, species kg/m³ and species kg per represented box. A state with no resolved slots and a PDF with a valid grid and all-zero population both have zero density, but have different shapes. ## Implementation order

1. **Define and test the CPU weights in the particle layer.** Use a concrete particle-owned internal function for validated native state, returning fresh float64 weights shaped (boxes, slots). Start with the existing slot-density read; apply trapezoidal widths only for a PDF. Factor the node-width arithmetic so the standalone optics array API and native code share it without constructing synthetic ParticleData or introducing a particles-to-optics dependency. Keep array-specific metadata and validation at the array boundary. Preserve the species-mass contraction's avoidance of a (boxes, slots, species) scratch array. Leave the independent number integral intact if consolidation would change reduction order needlessly. Done when raw optics still accepts its supported leading shapes, the native helper handles multiple boxes, and each result matches an independent oracle.
2. **Move physical readers across one at a time.** Preserve the one-box input check and flat return of `condensation_population_weights`; use its existing callers to reach ordinary and staggered condensation. Switch `population_optics` to the native weights and retain its empty result, validity masks, radius selection and material checks. Examine dilution and wall-loss rate reads with invalid and zero-work tests before replacing their inline division. A true raw write or identity check stays direct. Done when coupled mass/energy and per-wavelength optical outputs agree with their references and a detached read cannot mutate state.
3. **Mark the two opposite write conversions.** In binned coagulation stage the validated density increment into a candidate raw array, then commit with the existing in-place copy after the whole candidate passes. Under 0.3.6 the conversion for PMF/PDF is the identity. Keep zero-step behavior, finite/shape validation and the smaller-step error. In grid pack, convert density to count with each physical cell volume; unpack performs the inverse into detached copies and reconstructs kg per particle from species kg/count. A narrow adapter-local conversion is sufficient. Test individual packed lanes against independent numbers before testing reversal. Done when a broadcast of the first cell's volume fails the test and invalid proposals preserve the input arrays.
4. **Review the device counterparts and close the inventory.** Native Warp metadata codes are discrete 1, PDF 2, resolved 3; native transfer rejects PDF. The standalone optical array kernel uses discrete 0, resolved 1, PDF 2 and accepts a PDF radius grid. Passing these codes interchangeably would silently select the wrong formula. Unify only equivalent native device arithmetic and retain the array-kernel contract, rejection flags, direct launch boundaries, precision and caller-owned buffers. Exercise both direct and prepared execution after any affected device edits. Finish with the inventory, focused and repository validation results, exact device evidence and explicit #1752 handoffs in the PR.
