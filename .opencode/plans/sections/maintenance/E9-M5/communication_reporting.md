# Communication and Reporting

- Report phase progress to the issue #1602/E9 maintainer and M4/M6 owners in
  each phase PR; named reviewers remain to be assigned. Review inventory
  completeness at P1 and again before M6 handoff, not only changed-file lists.
- Each report includes exact supported sources/pairs migrated, unaffected rows,
  native contract revision, scientific comparisons, historical exceptions and
  literal commands/results with environment and final revision. Distinguish
  assertion success, coverage evidence, strict rendering and notebook execution.
- Escalate missing native capabilities, normalization disagreements, unsupported
  scientific changes and required unavailable execution immediately; block
  affected phases and reopen upstream gates rather than silently weakening tests.
- Keep phase evidence and remaining questions in this plan/linked PR ledger.
  At P7 deliver inventory, pair/output evidence, docs regression results, strict
  build, full-suite coverage and legacy-history allowlist to M6 for acceptance.
- Draft status is not shipped status. Do not start M6 removal until M5 is
  completed and validated. M5 cannot certify v0.3.0 release readiness or convert
  existing GPU measurement gaps into measured claims.
