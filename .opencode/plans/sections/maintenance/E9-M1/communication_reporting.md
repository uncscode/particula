# Communication and Reporting

- Report phase entry, completion and blockers in the implementation PR and
  issue #1602/E9 handoff record. Notify the maintainer and scientific reviewer;
  named implementation owners remain unassigned, not presumed from this draft.
- At P1 review, publish the concentration ledger and ordered species decision.
  At P2 review, request explicit API/copy-view/replacement approval from the
  maintainer and prospective M2 owner before helper implementation continues.
- Each PR records changed helpers, preserved assertions, exact focused commands
  and results, and any protected transfer/export impact. Keep test outcomes,
  documentation results and planning status separate.
- P5 reports revision/date, full required validation results, optional device
  skips, open questions, and the M2 acceptance packet. Required unavailable
  evidence is a blocker, never a pass. Only completed-and-validated M1 admits M2.
- Review metrics at every phase gate; no arbitrary calendar cadence or deadline
  is assigned. Escalate schema/physics/ownership changes rather than expanding
  T1 into downstream migration work.
- Any temporary compatibility entry needs path, reason, consumer, owner and M6
  removal gate. No new diagnostic/telemetry track is requested or authorized.
- Log significant decisions in this plan's change log and notify the E9 owner
  to reconcile parent/sibling records; this drafting task edits E9-M1 only.
