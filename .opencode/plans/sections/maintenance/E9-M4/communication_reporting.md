# Communication and Reporting

- Report phase starts, validated completions and blockers in the owning PR,
  issue #1602 and E9 workflow messages. Notify the E9 maintainer and M3/M5/M6
  owners at handoffs; named gate reviewers remain to be assigned.
- Each PR records before/after state authority, changed symbols, native fixture
  migration, preserved failure boundary, exact commands/results and any remaining
  compatibility consumers. Review metrics at each phase gate, not on an invented
  calendar cadence.
- Escalate species mapping, normalization, environment-signature or native
  topology conflicts before implementation; do not resolve them by adding a
  replacement facade, widening exports or weakening rejection/atomicity.
- Record unavailable evidence and optional device skips explicitly. Do not mark
  completed-and-validated based only on focused tests, drafting validation or
  successful optional CUDA skips.
- P5 handoff sends M5 tested native composition/adapter call patterns and
  failure/ownership guidance; sends M6 every temporary seam and deletion owner.
  Keep all sibling plans unchanged in this drafting task.
- Initial report: five Not Started phases, twelve first-pass sections, Draft
  plan, no implementation or test-run claims. Workflow completion distinguishes
  plan validation from later implementation acceptance.
