# Dependencies

Parent: E9, issue #1602. Direct metadata prerequisite: E9-M5.

`E9-M1 -> E9-M2 -> E9-M3 -> E9-M4 -> E9-M5 -> E9-M6`

Every arrow means completed and validated. No parallel implementation, no
early deletion, and no promotion based merely on draft/merged status. P1–P6
are also serial. Upstream changes reopen affected evidence gates.

| E9 parent / release review | Receives M6 zero-consumer/zero-seam audits and final readiness evidence; release approval remains explicit |

If P1 discovers a consumer not migrated by its owner, block and return the
finding upstream. Do not absorb uncompleted T1–T5 work into a deletion phase.
If a legacy-named utility serves enduring science, preserve or use its already
approved native replacement; name alone is not a deletion criterion.

Existing GPU conversion, direct kernels, resident lifecycle/RNG/checkpoint and
capture contracts are protected dependencies, not new feature work. Existing
GPU measurement gaps stay separate; Epic I follows E9, not vice versa.

No new external dependency. Use repository NumPy/SciPy, pytest, Warp, Ruff/mypy,
MkDocs and notebook tooling. Record optional runtime/device/package availability
and required execution blockers rather than inferring successful evidence.
