## Review and completion protocol

- Review each track's contract and affected behavioral coverage before code
  changes. Freeze M1 decisions before M2 admission.
- Before every handoff, record implementation revision, migrated consumers,
  test/lint/doc outcomes and remaining compatibility items. Approval requires
  predecessor completion and validation, not merely plan status.
- Track temporary bridges with path, rationale, consumer, owner and M6 deletion
  proof. An unresolved bridge or supported legacy consumer blocks closeout.
- Treat scope/contract changes as explicit decisions here and reopen impacted
  downstream gates. Do not bypass serial order to absorb a late change.
- Distinguish optional device skips from required unavailable evidence and
  planning completion from implementation shipment. E9 remains Draft.
