      Does update ordering change a condensation calculation?

      Section titled “Does update ordering change a condensation calculation?”

      Particles compete for a shared vapor reservoir. Updating that reservoir between particle batches changes the numerical coupling, even when all methods preserve total material. This CPU example compares three staggered update modes, then a larger-step trajectory and several batch counts.

      The useful question is how to separate conservation from trajectory accuracy. Start with finite-reservoir condensation. The comparisons below provide bounded evidence for these initial conditions; they do not rank methods universally or replace a timestep-convergence study.

      Python · section 1

      Fix the common vapor state

      Section titled “Fix the common vapor state”

      All comparisons start from the same water concentration: 1.025 times pure-water saturation at 298.15 K and 101325 Pa. There is one condensable material, no sources or sinks, and fixed temperature. Updating gas concentration allows particles to compete for finite water; the initial saturation ratio is not maintained.

      Python · section 2 
      Initial water concentration: 2.360191e-02 kg/m^3
Saturation concentration: 2.302625e-02 kg/m^3

      Hold the sampled population fixed across methods

      Section titled “Hold the sampled population fixed across methods”

      The population contains 1,000 water droplets in 1 cm³, with lognormally sampled radii around a 100 nm scale and density 1,000 kg m⁻³. Each method receives copies of the same containers, so one run cannot change the next run’s initial state. The fixed seed controls this comparison; it does not supply an ensemble error bar. Surface curvature remains part of the mass-transfer calculation.

      Created 1000 particles
Initial total particle mass: 1.186594e-14 kg
Mean particle radius: 111.3 nm

      Change how the timestep is partitioned

      Section titled “Change how the timestep is partitioned”
      Mode Split What changes
      half θ = 0.5 Equal-duration passes
      random θ sampled between 0 and 1 Random division between passes
      batch θ = 1 Batch updates without the second-duration contribution

      The runs below use ten batches, a 0.01 s timestep, and a shared seed. Shuffling is enabled, so equal-duration passes do not by themselves imply fixed particle ordering. Compare the printed final particle masses, then inspect the total material budget separately. No mode is designated “best” by this setup.

      Check a conserved quantity, not the whole solution

      Section titled “Check a conserved quantity, not the whole solution”

      For this single-material closed system, add extensive particle and gas masses and evaluate . The runnable wrapper asserts conservation with rtol=1e-12 and atol=1e-30; the plotted 10⁻¹⁰ line is a visual reference, not the assertion’s tolerance.

      The saved final relative errors are near 10⁻¹⁵ for all three modes. Differences at that scale do not rank trajectory accuracy. A curve can conserve total mass while distributing it incorrectly between gas and different particle sizes.

      Compare a larger timestep under the same initial conditions

      Section titled “Compare a larger timestep under the same initial conditions”

      The next experiment uses 0.1 s steps for 5 s and compares random staggered updates with simultaneous updates. Read particle mass and total-mass error as separate diagnostics. Both histories remain finite in this saved calculation; that observation neither demonstrates instability of the simultaneous method nor guarantees stability for another particle loading or timestep.

      Python · section 6

      Treat batch count as a numerical choice to investigate

      Section titled “Treat batch count as a numerical choice to investigate”

      One, five, ten, and twenty batches change how frequently gas feedback is applied. The final plot reports total-mass error only. It does not measure execution cost, particle-size error, or convergence toward a reference solution, so it cannot justify a particle-count-based recommendation for batch number.

      To choose a batch count for a study, compare gas concentration and size-resolved mass transfer against a sufficiently refined timestep, then measure cost for the intended population. Keep initial conditions and random-stream policy consistent across those comparisons.

      Python · section 7

      Design the next numerical experiment

      Section titled “Design the next numerical experiment”

      The displayed runs conserve the combined water inventory, yet update ordering and batch count remain separate numerical choices. Conservation is necessary for this closed system but is not enough to select an accurate trajectory.

      A useful extension is a timestep ladder for each mode, comparing final vapor, particle-mass quantiles, and the time of a defined growth event. Repeat seeded runs where random ordering matters and report both sensitivity and runtime. Only then select settings for a scientific question. See the condensation strategy guide for supported behavior and the numerical-methods topic for connections to other validation examples.
